# 巨量引擎方舟停推自动化工具 PRD

## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 产品名称 | 巨量引擎方舟停推自动化工具 |
| 文档版本 | v0.1 |
| 编写日期 | 2026-06-26 |
| 当前阶段 | MVP 需求梳理 |
| 目标用户 | 本地生活维修业务运营人员、投放操作人员 |

## 2. 项目背景

公司运营多个维修类目的本地生活业务，通过巨量引擎「巨量本地推-升级版」进行广告投放。当某些业务线或品类需要暂停推广时，当前需要人工进入不同代理商的已登录浏览器，在多个账户中逐个修改定向包的行政区域，并上传停推所需的 CSV 文件。

当前人工流程高度重复，单账户约 2 分钟，且存在漏操作、无日志、无法复盘、账户增长后人力成本线性增长等问题。因此需要建设一个轻量自动化工具，将重复页面操作交给系统执行，运营人员只负责配置任务、确认范围和监控结果。

## 3. 产品目标

### 3.1 业务目标

| 目标 | 说明 |
| --- | --- |
| 降低人工耗时 | 批量执行账户停推操作，减少逐账户手工点击 |
| 降低遗漏风险 | 按账户台账和规则筛选目标账户，减少人工漏选 |
| 增强可追溯性 | 记录每次任务、账户、步骤、结果和异常信息 |
| 支持规模增长 | 通过配置扩展账户和品类，不依赖额外人力堆叠 |

### 3.2 MVP 目标

MVP 阶段优先验证「自动化流程可跑通、结果可追踪、失败可定位」，不追求完整后台系统。

MVP 必须支持：

- 导入或维护账户台账。
- 创建停推任务。
- 按业务线或指定账户筛选目标账户。
- 执行前预览命中账户并人工确认。
- 在四个代理商各自已登录的浏览器中，通过插件自动完成单账户停推流程。
- 批量串行执行多个账户。
- 记录账户级和步骤级日志。
- 失败时记录错误原因，并保存可发送给业务或开发排查的日志。

## 4. 范围定义

### 4.1 MVP 范围

| 模块 | MVP 能力 |
| --- | --- |
| 账户台账 | 支持在油猴面板中维护账户备注列表 |
| 任务配置 | 支持按业务线、按指定账户创建任务 |
| 任务预览 | 展示命中账户数、账户列表、定向包和 CSV 文件 |
| 人工确认 | 任务必须确认后才可正式执行 |
| 页面执行 | 自动进入账户、关闭弹窗、进入定向包、上传 CSV、保存 |
| 执行日志 | 记录任务、账户、步骤、状态、错误信息 |
| 失败处理 | 单账户失败不影响后续账户，支持后续补跑依据 |
| 多代理商约束 | 四个代理商分别打开各自浏览器，由插件在当前浏览器内执行 |

### 4.2 非 MVP 范围

| 能力 | 说明 |
| --- | --- |
| 平台接口逆向 | 首版不直接调用巨量引擎内部接口 |
| 复杂权限系统 | 首版只面向本地运营使用 |
| 多人协同后台 | 首版不建设企业级后台 |
| 自动登录 | 首版复用已有浏览器登录态 |
| 全自动无确认执行 | 为避免误操作，首版保留人工确认 |
| 按品类自动停推 | 需补齐品类映射后进入第二阶段 |
| 多浏览器并行执行 | MVP 不做自动浏览器调度，由人工打开对应代理商浏览器后执行插件 |

## 5. 用户角色

| 角色 | 主要职责 |
| --- | --- |
| 运营人员 | 创建停推任务、确认命中账户、查看执行结果 |
| 投放负责人 | 维护账户台账、确认业务线和停推范围 |
| 开发人员 | 维护自动化脚本、选择器、日志和任务模块 |

## 6. 核心业务规则

### 6.1 账户备注规则

巨量本地推工作台账户备注格式为：

```text
负责人+店铺名称+代理商+业务线
```

示例：

```text
周涛+同城电器维修服务预约店+红马+家电
```

解析结果：

| 字段 | 示例 |
| --- | --- |
| 负责人 | 周涛 |
| 店铺名称 | 同城电器维修服务预约店 |
| 代理商 | 红马 |
| 业务线 | 家电 |

### 6.2 停推维度

| 维度 | MVP 支持 | 说明 |
| --- | --- | --- |
| 按业务线 | 支持 | 例如停推家电业务线下所有启用账户 |
| 按指定账户 | 支持 | 运营直接指定账户备注或账户 ID |
| 按品类 | 暂缓 | 需要账户台账补充品类字段后支持 |

### 6.3 执行规则

- 仅处理账户台账中 `enabled = true` 的账户。
- 任务执行前必须展示命中账户并由人工确认。
- 一个业务线下可能存在多个定向包，例如空调定向包、电视定向包；系统按任务中指定的 `packageNames` 逐个精确查找和修改。
- 每次任务只指定并上传一个定向包 CSV 文件，所有命中账户共用该文件。
- 不同代理商在各自浏览器中安装并执行同一个插件。
- 如果找不到账户、找不到定向包或存在多个同名定向包，该账户标记失败。
- 单账户失败后继续执行下一个账户，除非连续失败达到系统保护阈值。
- 每个关键步骤都需要记录日志。

## 7. 功能需求

### 7.1 账户台账管理

#### 7.1.1 功能说明

系统通过油猴面板中的账户备注列表识别哪些账户需要参与停推。MVP 不建设数据库后台，账户信息随表单配置一起保存。

#### 7.1.2 字段设计

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| accountId | string | 是 | 本地唯一 ID |
| accountRemark | string | 是 | 工作台中的账户备注 |
| owner | string | 是 | 负责人 |
| storeName | string | 是 | 店铺名称 |
| agent | string | 是 | 代理商 |
| browserType | string | 是 | 对应代理商浏览器标识 |
| businessLine | string | 是 | 业务线 |
| category | string | 否 | 品类，MVP 可为空 |
| packageNames | string[] | 否 | 账户默认需要修改的定向包名称列表，任务中可覆盖 |
| enabled | boolean | 是 | 是否参与自动化任务 |

#### 7.1.3 验收标准

- 能读取本地账户台账文件。
- 能校验必填字段缺失并输出错误。
- 能按业务线筛选账户。
- 能按指定账户 ID 或账户备注筛选账户。

### 7.2 停推任务创建

#### 7.2.1 功能说明

运营人员通过任务配置定义本次停推范围、目标定向包来源、本次上传的 CSV 文件路径和执行选项。

#### 7.2.2 任务配置字段

| 字段 | 说明 |
| --- | --- |
| 任务名称 | 本次停推任务名称 |
| 执行模式 | 按业务线或按账户备注 |
| 代理商 | 当前浏览器对应代理商 |
| 业务线 | 本次要停推的业务线 |
| 定向包名称 | 一个或多个定向包名称，一行一个 |
| 账户备注 | 一行一个账户备注 |
| dryRun | 是否只试跑、不保存 |
| CSV 文件 | 正式执行时选择本次上传的 CSV |

#### 7.2.3 验收标准

- 能读取任务配置。
- 能校验任务名称、执行模式、定向包名称、账户备注等必填字段。
- 能校验 CSV 文件存在。
- 能在当前任务中使用同一个指定 CSV 文件。
- 能在同一个账户内按任务指定顺序处理多个定向包。
- 能根据任务配置生成待执行账户列表。

### 7.3 任务预览与确认

#### 7.3.1 功能说明

正式执行前，系统必须展示本次任务将影响的账户范围，避免误操作。

#### 7.3.2 预览内容

| 内容 | 说明 |
| --- | --- |
| 任务名称 | 当前任务名称 |
| 执行模式 | 按业务线或指定账户 |
| 命中账户数 | 本次将处理的账户数量 |
| 账户列表 | 账户备注、代理商、业务线、定向包列表 |
| CSV 文件 | 本次导入的行政区域 CSV |
| 浏览器 | 本次需要在哪个代理商浏览器内执行 |
| 风险提示 | dryRun 状态、是否正式执行 |

#### 7.3.3 验收标准

- 未确认时不得进入正式执行。
- 预览列表和实际执行列表一致。
- 当命中账户数为 0 时，不允许执行。

### 7.4 浏览器页面执行

#### 7.4.1 功能说明

在已登录巨量引擎的浏览器环境内，自动完成账户停推页面操作。

#### 7.4.2 单账户流程

1. 打开或确认处于巨量本地推升级版工作台。
2. 使用工作台账户搜索能力，根据 `accountRemark` 搜索并定位目标账户。
3. 点击进入目标账户。
4. 检测并关闭活动弹窗。
5. 进入「工具 > 定向包」。
6. 根据 `packageNames` 逐个查找目标定向包。
7. 点击「修改」。
8. 点击「编辑」并进入「用户定向」。
9. 找到「行政区域」。
10. 点击「批量添加」。
11. 上传配置中的 CSV 文件。
12. 点击「编辑并关闭」保存。
13. 根据页面明确成功提示校验保存成功。
14. 返回工作台或准备处理下一个账户。

#### 7.4.3 执行状态

| 状态 | 说明 |
| --- | --- |
| pending | 等待执行 |
| running | 正在执行 |
| success | 执行成功 |
| failed | 执行失败 |
| skipped | 跳过 |
| retrying | 重试中 |

#### 7.4.4 验收标准

- 能在单账户中完整跑通停推流程。
- 弹窗存在时能关闭，弹窗不存在时继续执行。
- 找不到账户或任一定向包时不会误点其他元素，并记录具体定向包名称。
- 上传 CSV 后能触发保存。
- 保存成功以页面明确成功提示为准，失败必须可被日志识别。

### 7.5 日志与审计

#### 7.5.1 功能说明

系统需要记录任务级、账户级、步骤级日志，用于复盘和失败补跑。

#### 7.5.2 日志字段

任务级日志：

| 字段 | 说明 |
| --- | --- |
| taskId | 任务 ID |
| taskName | 任务名称 |
| mode | 执行模式 |
| status | 任务状态 |
| totalCount | 总账户数 |
| successCount | 成功数 |
| failedCount | 失败数 |
| startedAt | 开始时间 |
| finishedAt | 结束时间 |

账户级日志：

| 字段 | 说明 |
| --- | --- |
| taskId | 任务 ID |
| accountId | 账户 ID |
| accountRemark | 账户备注 |
| agent | 代理商 |
| businessLine | 业务线 |
| packageName | 当前执行的定向包名称 |
| status | 执行状态 |
| retryCount | 重试次数 |
| errorMessage | 错误信息 |
| logPath | 可发送的详细日志路径 |

步骤级日志：

| 字段 | 说明 |
| --- | --- |
| taskId | 任务 ID |
| accountId | 账户 ID |
| stepName | 步骤名称 |
| status | 成功或失败 |
| detail | 补充信息 |
| timestamp | 时间 |

#### 7.5.3 验收标准

- 每个任务生成一份执行汇总。
- 每个账户生成一条账户级结果。
- 失败账户能看到失败步骤和错误原因。
- 日志可导出为 JSONL 或 CSV。

## 8. 非功能需求

### 8.1 稳定性

- 页面关键操作必须设置超时时间。
- 页面加载慢时需要等待，不直接失败。
- 连续失败达到阈值时暂停任务。
- 单账户失败不得导致整个任务进程崩溃。

### 8.2 安全性

- 不保存巨量引擎账号密码。
- 仅复用当前已登录浏览器环境。
- 执行前由插件确认当前浏览器对应的代理商和任务范围。
- 正式执行前必须人工确认。
- 支持 dryRun，仅验证账户匹配和页面路径，不提交保存。

### 8.3 可维护性

- 页面选择器集中维护。
- 关键按钮文案和选择器支持多候选配置。
- 账户台账、任务配置、执行日志分离。
- 错误码需可读，便于运营反馈给开发。

## 9. 技术实现建议

### 9.1 推荐形态

MVP 推荐使用油猴脚本：

- Tampermonkey 脚本：安装到四个代理商各自浏览器中，负责任务导入、预览、页面点击、CSV 上传、保存和日志导出。
- 面板表单：在油猴面板中填写账户列表、停推范围、定向包名称和执行选项。
- 日志导出：脚本内生成 JSONL 日志，支持复制或下载。
- 运行上下文：由当前浏览器决定代理商身份，MVP 不做浏览器和 IP 代理自动调度。

### 9.2 推荐目录结构

```text
youhou/
  docs/
    juliang-stop-push-prd.md
    operator-runbook.md
  config/
    accounts.sample.json
    task.sample.json
  tampermonkey/
    juliang-stop-push.user.js
    task.example.json
    README.md
```

### 9.3 首版技术原则

- 先跑通一个代理商浏览器、一个业务线。
- 先支持串行执行，避免上下文冲突。
- 所有危险操作前先 dryRun。
- 选择器和业务逻辑分离。
- 每个失败都有可读日志，不沉默失败。

## 10. 异常场景

| 异常 | 处理方式 |
| --- | --- |
| 账户未找到 | 当前账户失败，记录 `ACCOUNT_NOT_FOUND` |
| 定向包未找到 | 当前账户失败，记录 `PACKAGE_NOT_FOUND` |
| 出现多个同名定向包 | 当前账户失败，记录 `PACKAGE_DUPLICATED` |
| 弹窗关闭失败 | 记录详细日志并标记 `POPUP_CLOSE_FAILED` |
| CSV 上传失败 | 按配置重试，仍失败则记录 `CSV_UPLOAD_FAILED` |
| 保存失败 | 记录 `SAVE_FAILED` |
| 页面超时 | 刷新或重试当前账户，超过次数后失败 |
| 连续失败过多 | 暂停整个任务，等待人工检查 |

## 11. 验收清单

### 11.1 MVP 验收

- 能读取账户台账并完成字段校验。
- 能读取任务配置并生成命中账户列表。
- 能展示任务预览，并要求人工确认。
- 能对单个账户完成完整页面停推流程。
- 能对多个账户串行执行。
- 能记录成功、失败和跳过结果。
- 能定位失败发生在哪个步骤。
- dryRun 模式下不会提交最终保存。

### 11.2 业务验收

- 使用 3 个测试账户进行试跑。
- 至少 1 个成功账户能验证行政区域已更新。
- 至少 1 个异常账户能验证失败日志可读。
- 运营人员能根据日志判断是否需要补跑。

## 13. 已确认约束

| 问题 | 结论 | 对方案的影响 |
| --- | --- | --- |
| 巨量本地推工作台账户列表是否支持搜索备注 | 支持 | 账户定位优先使用备注搜索 |
| 定向包名称是否需要统一规则 | 暂不强约束 | MVP 按任务指定的 `packageNames` 精确匹配，可一次指定多个 |
| CSV 文件是否需要按业务线维护路径和命名规范 | 不需要 | 每次任务只上传一个指定 CSV 文件，文件命名由执行人编辑 |
| 不同代理商是否必须使用不同浏览器 | 是 | 四个代理商各自打开浏览器并安装插件执行，系统不管理 IP 代理 |
| 行政区域上传后是否有明确成功提示 | 是 | 保存校验以页面成功提示为准 |
| 是否需要保留每次失败截图 | 不需要 | 仅保存可发送的执行日志，不强制截图留档 |
