# 开发拆解

## 1. MVP 开发顺序

| 阶段 | 目标 | 产出 |
| --- | --- | --- |
| 1 | 油猴面板 | 表单输入、按钮、日志区域 |
| 2 | 配置读取与校验 | 账户列表解析、任务配置解析、错误提示 |
| 3 | 任务预览 | 命中账户列表、人工确认、dryRun 标识 |
| 4 | 单账户执行器 | 跑通一个账户的页面停推流程 |
| 5 | 批量调度 | 在当前代理商浏览器内串行执行、失败不中断 |
| 6 | 日志审计 | 任务日志、账户日志、步骤日志 |
| 7 | 异常与补跑 | 失败错误码、失败账户导出、补跑任务 |

## 2. 建议模块

| 模块 | 职责 |
| --- | --- |
| panel | 渲染油猴悬浮面板、任务输入和按钮 |
| task-parser | 从表单构建任务对象、校验字段、筛选账户 |
| preview-service | 生成执行前预览数据 |
| executor | 页面自动化执行核心 |
| selector-registry | 维护巨量页面搜索、按钮和成功提示选择器 |
| log-service | 在面板内输出 JSONL 日志，支持复制和下载 |
| retry-service | 控制单账户重试和失败补跑 |

## 3. 首个开发里程碑

第一个里程碑只要求完成「油猴面板内不提交页面」的闭环：

1. 在巨量页面加载油猴面板。
2. 填写面板表单。
3. 校验配置字段。
4. 根据业务线筛选账户。
5. 校验本次任务指定的多个定向包名称。
6. 输出预览列表。
7. 校验本次任务指定的 CSV 文件和当前浏览器代理商范围。
8. dryRun 模式下生成一份模拟执行日志。

完成这个里程碑后，再接入浏览器页面执行器，风险会低很多。

## 4. 用户执行步骤先行验证

开发前先用 `docs/operator-runbook.md` 和 `tampermonkey/README.md` 验证真实操作链路，确认运营实际只需要提供以下内容：

| 内容 | 来源 |
| --- | --- |
| 当前代理商 | 当前打开的浏览器 |
| 停推范围 | 业务线或指定账户 |
| 定向包名称 | 本次任务手动填写，可填写多个 |
| CSV 文件 | 本次任务手动选择一个文件 |
| 是否 dryRun | 首次执行先 true，确认后 false |

## 5. 建议操作形态

| 操作 | 入口 |
| --- | --- |
| 预览 | 油猴面板「预览」按钮 |
| dryRun | 油猴面板中保持 `dryRun: true` 后点击「执行」 |
| 正式执行 | 选择 CSV，将 `dryRun` 改为 `false` 后点击「执行」 |
| 停止 | 油猴面板「停止」按钮 |
| 导出日志 | 油猴面板「复制日志」或「下载日志」 |

## 6. 关键验收点

| 验收点 | 判断标准 |
| --- | --- |
| 配置校验 | 缺字段、路径不存在、模式错误时能给出明确错误 |
| 预览准确 | 预览账户列表和实际执行账户一致 |
| dryRun 安全 | dryRun 不触发保存动作 |
| 页面执行 | 单账户能通过备注搜索定位账户，并根据明确成功提示确认保存 |
| 日志可读 | 运营能看到哪个账户、哪一步、为什么失败 |
